## 18. Retrospective Validation — Does Acting on High-Priority Predictions Associate With Better Outcomes?

Sections 5b/5c establish the priority model's accuracy/F1 against real outcomes — but that comparison is necessarily circular in one specific way: `Priority_Label` was *built from* the outcome (`score`, `submitted_late`, Section 4), so "do High-priority tasks turn out worse than Low-priority ones?" is true by construction and proves nothing new. This section runs the one methodologically valid retrospective test available: **hold the model's prediction fixed and look for variation in behavior the prediction doesn't already encode.** Within tasks the deployed monotonic model (Section 5c) predicted High priority — from pre-outcome features only, on the same held-out test set Sections 5b/5c report metrics on — did students who behaviorally responded with more urgency (`clicks_trend > 0`, an "acted with urgency" proxy) actually achieve better real outcomes than those who didn't? This is genuinely non-circular: the prediction is constant across the comparison groups, so it tests whether *acting* on an elevated signal associates with results, not whether the signal correctly identified risk (already covered by 5b/5c).

**Method.** `ml_scripts/study-planner/retrospective_validation.py` reconstructs `score`/`submitted_late` (dropped from the exported feature CSV specifically so they can never leak into the model) by re-running only the row-order-determining, non-VLE steps of the original data pipeline, then verifies the reconstruction against the exported CSV before trusting it — 100.0000% exact match on `Priority_Label`, `weight`, and `date` across all 170,874 rows, checked programmatically, not assumed. Welch's t-test + Cohen's d for score, chi-square + risk difference for lateness, run within the High-priority-predicted subset (core comparison) and, identically, within the Low-priority-predicted subset (falsification/control check — if the effect is genuinely specific to high-stakes situations, it should be weaker or absent there). Logistic/OLS regression controlling for `weight` and `prior_avg_score` run in both subsets to check whether any raw association survives confounding.

**Result: the core hypothesis was NOT supported, and the falsification check was decisive, not just weaker.**

- **Score**: urgency-responsive students scored *slightly lower*, not higher, in both subsets (Cohen's d = -0.119 High, -0.071 Low — small, wrong-direction effects) — and neither survived confound control (both non-significant, p=0.19 and p=0.34, once `weight`/`prior_avg_score` were included). No credible score effect.
- **Lateness**: within the High-priority subset alone, urgency-responsive students *were* less often late (risk difference -6.9pp, p<10⁻⁸), even surviving confound control (logistic coefficient -0.448, p<10⁻⁶) — superficially supportive. But the identical analysis on the Low-priority control subset showed a statistically significant effect of the **opposite sign** (risk difference +2.9pp; confound-controlled coefficient **+0.447**, p<10⁻⁵) — not weaker, *reversed*. Per the task's own falsification criterion, this fails specificity to high-priority situations outright, and is reported as such rather than selectively citing only the High-priority result.

**Interpretation.** This is a purely observational, correlational backtest on historical OULAD data — it cannot establish causation, and critically, these students never saw this system, this UI, or any priority prediction from it; `clicks_trend` reflects incidental historical behavior, not a response to a recommendation. **The honest conclusion is a null/failed-replication finding**: no credible evidence that behaviorally responding with urgency to a high-priority prediction specifically associates with better historical outcomes. The one effect that looked supportive (lateness) is very likely an artifact of some confound correlated with the priority-bucket split (e.g. module/assessment-type composition) rather than genuine priority-driven urgency, given it reverses sign in the control subset. This does not diminish Sections 5b/5c's validated predictive accuracy — it specifically means "and therefore acting on it helps" is *not* established by this analysis and should not be claimed. **This does not substitute for real pilot testing (Section 14, Objective 7)** — a live pilot measures what this backtest structurally cannot: whether real students who actually see this system's recommendations change behavior in response, and whether that changes outcomes. Full statistics: `ml_scripts/study-planner/outputs/retrospective_validation_report.md` / `retrospective_validation_results.csv`.
