# Retrospective Validation — Does Acting With Urgency on High-Priority-Predicted Tasks Associate With Better Outcomes?

Generated by `ml_scripts/study-planner/retrospective_validation.py`, against the deployed `OrdinalMonotonicPriorityModel` (Section 5c) and the held-out test set (same 20% split, `random_state=42`, as Sections 5b/5c — for direct comparability with the model's already-reported accuracy/F1). **No production code was changed.**

## Why this is NOT "do High-priority tasks have worse outcomes than Low"

`Priority_Label` was built *from* the task's real outcome (`score`, `submitted_late` — Section 4). Checking whether High-priority tasks have worse outcomes than Low-priority tasks is tautological — true by construction, and would prove nothing. This analysis instead **holds the predicted priority fixed** and asks a genuinely different, non-circular question: *within* the set of tasks the model predicted High priority (from pre-outcome features only, exactly as production does), did students who behaviorally responded with more urgency actually do better than those who didn't? The prediction is constant across the comparison groups — this tests whether *acting* on an elevated signal associates with better results, not whether the label correctly identified risk (already established by Sections 5b/5c, not re-tested here).

## Methodology note: reconstructing outcomes without re-running VLE processing

The exported `oulad_task_level_leakage_free.csv` deliberately has no `score`/`submitted_late` columns (dropped before export so they can never leak into the feature matrix). This script needed them back as *outcome-only* data. Rather than re-running the several-minutes chunked `studentVle.csv` aggregation, it re-ran only the row-order-determining steps (the non-VLE joins + the sort in Section 2, which depends only on `id_student`/`code_module`/`code_presentation`/`date` — none of them VLE-derived) and attached `score`/`submitted_late` to the exported CSV by position. **This was verified, not assumed**: before trusting the join, the script cross-checked that its freshly-recomputed `Priority_Label`, `weight`, and `date` matched the exported CSV's values at a **100.0000% exact rate** across all 170,874 rows — the script is written to abort loudly if this check fails. It didn't.

## Section 1: the "acted with urgency" proxy

```
urgency_responsive = 1 if clicks_trend > 0, else 0
```

`clicks_trend` (already engineered, Section 5b) = a student's most recent week's VLE clicks minus their *own* earlier average — positive means engagement rose relative to their own baseline heading into this assessment's deadline.

**Honest limitation**: this is a proxy for "behaviorally more engaged than usual around this deadline," not a direct measure of "the student prioritized *this* task because of an urgency signal." OULAD students never saw this system's predictions — this is historical, incidental behavioral variation, not a response to any actual recommendation. Rising engagement could reflect many things unrelated to this specific task (another assessment in the same window, general re-engagement with the module, unrelated life circumstances).

## Section 2/3: core comparison and falsification check

| Subset | n (urgent / not) | Mean score (urgent vs not) | Cohen's d | p (t-test) | Late rate (urgent vs not) | Risk diff | p (χ²) |
|---|---|---|---|---|---|---|---|
| **High-priority-predicted** | 1,549 / 7,619 | 69.70 vs 72.56 | **-0.119** | 1.8×10⁻⁵ | 0.715 vs 0.784 | **-0.069** | 4.0×10⁻⁹ |
| **Low-priority-predicted** (control) | 1,857 / 9,879 | 79.98 vs 81.16 | **-0.071** | 0.0071 | 0.091 vs 0.062 | **+0.029** | 4.3×10⁻⁶ |

**Score**: urgency-responsive students scored *lower*, not higher, in both subsets — the opposite direction from the hypothesis. Both effects are statistically significant (large sample sizes make even small effects detectable) but small in magnitude (Cohen's d ≈ -0.07 to -0.12, conventionally "small"). The High-subset effect (d=-0.119) is somewhat larger in magnitude than the Low-subset one (d=-0.071), but **both point the wrong way** relative to what "urgency response helps" would predict.

**Lateness — the falsification check is decisive here**: in the High-priority subset, urgency-responsive students *were* less often late (risk difference -0.069, i.e. 7.7pp lower late rate) — on its own, this would look like support for the hypothesis. But in the Low-priority-predicted control subset, the **same comparison reverses sign**: urgency-responsive students were *more* often late (risk difference **+0.029**), not less. Per the task's own falsification criterion — "if the effect is genuinely specific to high-priority, high-stakes situations, it should be much weaker or absent in Low-priority" — a **weaker-or-absent** effect would have been mildly reassuring; a **sign-reversed** effect is a stronger and more informative failure of specificity than that. This is reported plainly, not minimized.

## Section 4: confound control (regression)

Logistic regression on `submitted_late` and OLS on `score`, each `~ urgency_responsive + weight + prior_avg_score`, run in **both** subsets (the task required only the High-priority subset; the Low-priority regression was added here specifically because it extends the same falsification logic from Section 3 to the confound-controlled result, not just the raw comparison):

| Subset | Outcome | `urgency_responsive` coef. | p-value | Significant? |
|---|---|---|---|---|
| High-priority-predicted | `submitted_late` (logit) | **-0.448** | 2.8×10⁻⁷ | Yes |
| Low-priority-predicted | `submitted_late` (logit) | **+0.447** | 1.2×10⁻⁶ | Yes |
| High-priority-predicted | `score` (OLS) | -0.714 | 0.189 | No |
| Low-priority-predicted | `score` (OLS) | -0.369 | 0.342 | No |

**Score**: after controlling for `weight` and `prior_avg_score`, the small raw score differences from Section 2 are no longer statistically significant in *either* subset. The apparent "urgency-responsive students score slightly lower" pattern is not a robust, independent association once genuine confounds (assignment stakes, prior performance) are accounted for — most likely explained by those confounds rather than anything about urgency response itself.

**Lateness**: the effect *does* survive confound control — but it survives with **opposite signs in the two subsets** (-0.448 vs +0.447, both highly significant). This is the clearest, most decisive result in the whole analysis, and it is a **failed replication of the core hypothesis, not a supporting one**: a real, robust, confound-controlled statistical association between `urgency_responsive` and `submitted_late` exists in this dataset, but it is not specific to high-priority-predicted tasks — the same behavioral proxy predicts *opposite* lateness outcomes depending on which priority bucket a task fell into. That pattern is far more consistent with some other confound the regression didn't include (e.g., systematic differences in module/subject composition between what gets predicted High vs. Low, unrelated to "urgency" as a construct) than with "acting on high-priority signals reduces lateness."

## Section 5: honest interpretation

**This is a purely observational, correlational analysis of historical OULAD data.** It cannot establish that this system's recommendations *caused* better outcomes — OULAD students never saw this system or its priority predictions at all. At best it asks whether a historically-incidental behavioral pattern *consistent with* "acting on an urgency signal" is associated with better outcomes among students who, per the deployed model, faced similar predicted risk.

**Was the core hypothesis (Section 2) supported? No, not once the falsification check and confound control are taken seriously.**

- The **score** result pointed the wrong direction from the start (small, "urgency-responsive" students scored *lower*) and lost statistical significance entirely once `weight`/`prior_avg_score` were controlled for, in both subsets. No evidence here.
- The **lateness** result looked supportive in the raw High-priority comparison and even survived confound control — but the falsification check reveals this is **not specific to high-priority tasks**: the identical confound-controlled regression on the Low-priority control subset shows a statistically significant effect of the **opposite sign**. A real, non-circular signal exists in the data connecting `clicks_trend` to `submitted_late` — it just isn't the "priority-driven urgency helps" story the hypothesis proposed. It's more likely an artifact of something the priority-bucket split correlates with (e.g., which modules/assessment types tend to land in each bucket) than evidence that responding to a high-priority signal specifically improves punctuality.

**Overall: this backtest does not provide credible evidence that behaviorally responding with urgency to a high-priority prediction specifically associates with better historical outcomes.** This is reported as the actual result, not walked back — a null/failed-falsification finding here is a legitimate, useful output of the exercise (it correctly caught what would otherwise have been an overclaimed, partially-circular-adjacent "validation" story), not a failure of the methodology, which worked exactly as intended: it was specifically designed to be capable of producing this result if the data didn't support the hypothesis, and it did.

**This does not substitute for real pilot testing (Section 14, Objective 7) with actual students using the actual deployed system**, and should not be cited as if it did. The fundamental limitation is that every data point here comes from OULAD students who never interacted with this system, this UI, or these specific priority recommendations — `clicks_trend` here reflects whatever incidental, unrelated reasons a historical student's engagement happened to rise or fall, not a response to seeing "this task is High priority" on a screen. A live pilot would measure the thing this analysis structurally cannot: whether real students who *do* see this system's recommendations change their behavior in response, and whether that response improves their real outcomes. This retrospective analysis is the best available evidence without a live pilot — it is not a substitute for one, and the result above (a failed, sign-reversed replication) is itself a reason to treat any pre-pilot confidence in "the system's priority signal drives better behavior" as unsupported until tested live.
